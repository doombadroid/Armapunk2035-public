    server/fn_storeSql.sqf   native PostgreSQL. Upstream's declared dialect is
                             MariaDB (it has to be: extDB3 hosts still exist),
                             so upstream writes SELECT QUOTE(data) and
                             ON DUPLICATE KEY UPDATE. This host ripped MariaDB
                             out on 2026-08-20 and speaks PostgreSQL only, where
                             those are a double-quoted value and a syntax error.
    server/fn_srvInit.sqf    the HandleDisconnect flush is spawn-and-carry. The
                             handler is unscheduled, the store's save is a mode-2
                             read-back, and apdb refuses mode 2 outside a
                             scheduled context -- so upstream's inline call loses
                             the leaver's progress silently on this transport.
